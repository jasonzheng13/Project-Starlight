# Progress and ending

## User outcome

Exploration makes the sky feel increasingly personal and complete. Progress supports the experience without testing memory or trapping the recipient behind a task.

## Progress rules

- A memory counts as opened once its readable content is displayed. No minimum reading time, quiz answer, or video completion is required.
- The browser updates the visual state immediately and requests a save.
- Saving is idempotent: retries do not create duplicate records.
- A constellation is illuminated when its required memories have been opened. Optional memories do not block it.
- Derive progress from stable memory IDs, not coordinates or display order.
- On reload, fetch saved progress. If a save fails, keep the current session usable, explain briefly that it has not saved, and allow retry.
- Do not store private notes/media in browser storage simply to preserve progress.

## Ending

When the five constellations are complete, reveal a clear invitation to open the final message and Year VI. The letter and reveal are authored by the developer. Exact content and Year VI symbolism remain undecided.

Also provide a gentle continue-to-final-message route so fatigue, missing media, or a save problem cannot prevent the gift from finishing. This is discovery, not an access-control puzzle. No AI is allowed to decide whether affection or the final message has been earned.

Reopening the final message is always possible once reached. The owner can rehearse with separate test progress; resets must be explicit and must not delete memories. Public demo reset affects demo progress only.

## Acceptance checks

- Repeated and concurrent open events create one progress record per member/memory.
- Refresh restores the expected stars and constellation illumination.
- A failed save does not prevent continued browsing or the ending.
- Missing optional media does not block completion.
- The final message can be opened through both the ordinary completion route and the continue route.
- Rehearsal/demo reset does not modify private real progress or content unexpectedly.

Depends on the data rules, viewer, and constellation specs. Build the ending in the first full journey, not on the final evening.
