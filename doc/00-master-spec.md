# Master specification

Status: planning baseline. Updated September 17, 2026.

## Purpose

Build a beautiful, private website that expresses five years of care through selected memories, personal writing, constellation artwork, and hand-drawn loading animations. The couple will explore it together on a computer on September 28.

The developer also wants to grow primarily in backend application development and produce a strong portfolio piece. Gift quality and engineering learning are equally important. Keep the feature set focused so both receive attention.

## Confirmed direction

- Five year constellations with clickable memory stars.
- Exploration and gradual illumination, without puzzles or quizzes.
- Photos and videos from the relationship, with authored personal notes.
- Constellation visual inspiration from the supplied game screenshots; create personal artwork rather than copying game assets.
- Hand-drawn loading artwork and animation by the developer.
- A final personal reveal and a Year VI idea; exact content remains open.
- Private real content; a separate safe dataset for a future public portfolio demo.
- AI remains a desired optional addition if time permits.
- Maximum total initial project spending: $100. Free services preferred. Recurring costs must be visible.

## Main journey

Open website and establish private access -> see five constellations -> choose a year -> select a memory star -> view media and read a personal note -> continue exploring -> see the constellation become illuminated -> reach the final message.

The experience should feel easy to understand without instructions from the developer. A simple year list must offer an alternative to selecting stars. Return, next, mute, and continue controls must be clear.

## Required anniversary features

1. Five constellations, using replaceable placeholder symbols until final art is ready.
2. One complete memory viewer for photos, video, and text.
3. Personal writing attached to selected memories.
4. Private access and private media delivery.
5. Saved exploration progress and a reliable final reveal.
6. Personal loading art, honest loading behavior, and useful failure states.
7. A deployed version tested on the actual presentation computer.
8. A backup keepsake or recording and a rehearsed presentation.

Proposed content target: five key memories per year, approximately 25 total. This is a planning target, not a reason to include weak material. Additional memories are optional. A short main journey with longer optional browsing is preferred; exact duration will come from rehearsal.

## Optional and deferred work

AI memory search has its own preserved spec. Ambient sound is optional and must have a mute control. General-purpose authoring tools, multi-couple accounts, 3D reconstruction, voice commands, free-flight controls, puzzle engines, and automatic media interpretation are outside the anniversary commitment.

## Success checks

- The recipient can open and explore a memory without a tutorial.
- The content contains specific observations and personal details rather than generic captions.
- The entire journey can finish without AI or a third-party model service.
- Progress survives a refresh; media and final message remain reachable if a save fails.
- An unrelated visitor cannot fetch private metadata or media.
- The real computer runs the experience smoothly with all final content loaded.
- The developer can explain the data model, access rules, media flow, and deployment choices.

## How scope is managed

More available hours do not remove uncertainty. Prove one complete chapter before expanding. If progress slips, reduce optional features or the number of secondary memories. Do not trade away private access, the ending, or basic usability to add another system.

Final symbols, exact notes, final reveal content, target hardware, and provider choices are still open. See [the decision log](10-decisions-and-open-questions.md).
